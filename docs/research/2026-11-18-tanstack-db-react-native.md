# TanStack DB in the Expo app

- **Package compatibility.** The published React adapter `1.0.0-rc.1.5` uses DB `1.0.0-rc.1.5`. Query Collection `1.5.2` declares DB `^1.0.0-rc.0` and Query Core `^5.90.15` as peers. React Query `5.108.0` uses Query Core `5.108.0`. Resolve a single DB version and share the existing React Query client with the collection adapter. [React adapter package](https://registry.npmjs.org/@tanstack/react-db/1.0.0-rc.1.5) · [Query Collection package](https://registry.npmjs.org/@tanstack/query-db-collection/1.5.2) · [React Query package](https://registry.npmjs.org/@tanstack/react-query/5.108.0) · [TanStack DB RC guide](https://tanstack.com/db/latest/docs/guides/migrate-to-1-0-rc)
- **Browse boxes as live rows.** Query Collections use TanStack Query to fetch data and expose collection rows to `useLiveQuery`. The app can load a household’s box summaries into an eager collection keyed by box ID and sort them locally by box number. Keep search results in server order. The worker ranks semantic matches and checks item names beyond the six shown in a summary. Scope private box data to the household and signed-in session, including collection cleanup on sign-out. TanStack Query’s response cache and DB’s synced rows have separate lifecycles. [Query Collections](https://tanstack.com/db/latest/docs/collections/query-collection) · [Live queries](https://tanstack.com/db/latest/docs/guides/live-queries) · [Worker search](../../apps/worker/src/search.ts)
- **Refresh after writes and handle sync errors.** Query Collection 1.x mutation handlers require explicit synchronization through a refetch or an awaited write of the confirmed rows. Direct writes update synced data and representable Query cache entries without fetching. Server-ranked search needs a refresh after edits that affect matches. In a live query, `isLoadingError` describes a failed first load and `isSyncError` can surface later sync failures while rows stay visible. `reload()` retries a failed load. [RC mutation changes](https://tanstack.com/db/latest/docs/guides/migrate-to-1-0-rc#query-collection-handlers-no-longer-refetch) · [Direct writes and refetch](https://tanstack.com/db/latest/docs/collections/query-collection#direct-writes) · [Loading and sync errors](https://tanstack.com/db/latest/docs/guides/error-handling#loading-and-sync-errors)
- **Initialize native runtime support.** TanStack DB requires secure UUID generation. Its UUID helper accepts global `crypto.randomUUID` or `crypto.getRandomValues`. Expo SDK 58’s `expo-crypto` provides secure `randomUUID()` and can supply it on native when both globals are missing. Expo Router documents loading `expo-router/entry` last when using a custom entry to initialize globals. The native React Query integration uses `AppState` for foreground focus and `onlineManager` with `expo-network` for reconnects. Expo SDK 58 documents `expo-network` `~58.0.5` with an initial asynchronous network read and a removable listener.
